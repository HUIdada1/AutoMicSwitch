# AutoMicSwitch

> 切换 Windows 默认播放设备（耳机 / 音箱）时，自动把默认麦克风切到对应设备。带一个独立的主界面窗口。

**AutoMicSwitch** watches your Windows default playback device and automatically switches the default microphone to the matching one — so when you put on your headset, the headset mic becomes default; when you switch to speakers, the camera mic takes over. Ships with its own desktop window.

## 解决的问题

同时插着耳机、音箱、摄像头时，Windows 只认一套默认输入和输出。戴耳机开麦想用耳机麦，切到外放又得手动把麦克风换成摄像头麦，每次都要去声音设置里点两下。

这个程序常驻后台盯着默认播放设备，一旦变化，就按规则把默认麦克风一起切过去（通信麦克风也会设）。设备用硬件路径里的 `VID_xxxx` 识别，换 USB 口、改显示名、重装驱动都不会失效。

## 功能

- 默认播放设备变化 → 自动切换默认麦克风
- 独立窗口界面：当前设备、联动指标、规则配对板、设备清单、日志弹窗
- 规则直接在界面里拖拽配对，也可以先点左边再点右边，改完立刻生效，不用重启
- 覆盖 `rules.txt` 前自动留一份 `.bak`，写盘走临时文件替换，不会写出半个文件
- 黑 / 白 / 跟随系统三态主题，切换即时生效，窗口标题栏跟着走
- 设备清单里点一下就能切系统默认播放 / 录音设备，不用再翻声音设置
- 托盘常驻，可暂停 / 恢复、切主题、打开日志
- 安装时可选开机自启，装完也能在界面里随时开关
- 内置更新：查到新版本后下载、校验、静默替换并自动重启
- 规则也能手写 `rules.txt`，格式见下

## 运行环境

- Windows 10 / 11（更老的系统理论可用，没测过）
- .NET Framework 4.6.2 或更高，Windows 10 1803 以后基本都自带
- **WebView2 运行时**：界面靠它渲染。Windows 11 自带；Windows 10 通常随 Edge 一起更新装上
- 不需要管理员权限

安装程序在装之前会把上面三项挨个查一遍，缺哪个当场说明，不会装完打不开界面才让人猜。运行时缺失时程序本身不会崩，会弹一个原生提示窗口给出下载入口。

### 关于架构

安装包只有一个，主程序编译成 **AnyCPU**，同一个 exe 在 x64、x86、ARM64 上都能起：

- 64 位 Windows → 64 位进程
- 32 位 Windows → 32 位进程
- ARM64 Windows → .NET Framework 走 x86 仿真，32 位进程

真正需要按架构分的是 WebView2 的原生加载器 `WebView2Loader.dll`，位数和进程对不上会直接崩。所以安装包里同时带了三套（`runtimes\win-x86` / `win-x64` / `win-arm64`），运行时 SDK 自己按当前进程挑，装完不用管。

界面上「运行架构」那一格显示的就是实际跑起来的组合，比如 `x64 · 64 位` 或 `ARM64 · 32 位仿真`。

## 安装

下载 `AutoMicSwitch-Setup.exe` 双击运行，装到 `%LOCALAPPDATA%\AutoMicSwitch`，不写系统目录，全程不需要管理员权限。

安装时可勾选：

- 开机自动启动（默认勾选）
- 创建桌面快捷方式（默认勾选）
- 安装完成后立即运行（默认勾选）

装完从开始菜单或桌面图标启动，会直接弹出程序自己的窗口。带 `--startup` 启动时只驻留托盘，不弹窗口；之后再双击图标或点托盘菜单「打开主界面」，窗口会出来。

> 项目只提供安装版。装到固定目录是为了让开机自启的路径稳定，更新时也能整包替换。

批量部署想静默装：

```
AutoMicSwitch-Setup.exe /S            静默安装，装完不启动
AutoMicSwitch-Setup.exe /S /relaunch  静默安装并启动
```

## 主界面

窗口默认 1180×800，最小 980×640，可以自由缩放。内容从上到下：

- **顶栏**：程序状态（运行中 / 已暂停）、运行时长、运行架构，右上角是主题切换
- **当前设备**：左边播放输出、右边默认麦克风，两张小卡片，中间一个箭头表示联动方向。下面一行显示这次命中了哪条规则，走兜底时会亮一个黄色标记。发生切换的瞬间两张卡片闪一下
- **指标条**：联动切换次数、被改回重试次数、规则条数、兜底麦克风
- **联动规则**：上半部分是拖拽配对板，下半部分是已建立的规则列表
- **设备清单**：当前在线的播放设备和录音设备，默认设备高亮。**点任意一台就把它切成系统默认**，播放设备改完，联动规则会在下一轮自动跟上
- **底栏**：暂停 / 恢复联动、开机自启开关、检查更新、打开目录、查看日志

日志不占页面位置，点底栏「查看日志」弹出窗口看：最近 80 条，按级别着色（普通 / 成功 / 警告 / 错误），可以关掉自动滚动，也可以一键用记事本打开日志文件。弹窗按 `Esc`、点右上角 ✕ 或点空白处都能关掉。

窗口点右上角 ✕ 是**收进托盘**，不是退出——联动得一直跑着才有意义。第一次这么关会弹个气泡提示。真要退出走托盘菜单的「退出」。

窗口收进托盘后界面会停止轮询，不白烧 CPU；再打开时自动接着刷。

## 拖拽配对规则

配对板左边列出所有播放设备，右边列出所有录音设备，中间一个箭头。建规则有两种方式，随便挑：

- **拖**：按住左边的播放设备，拖到右边那台麦克风上松手。拖动时源项变半透明，落点会亮起边框
- **点**：先点一下左边的播放设备（它会高亮），再点右边那台麦克风

同一台播放设备只会有一条规则：再配一次就是换目标，不会堆出一串重复条目。建完会弹一个小提示告诉你配了哪两台。

规则列表每条一行，显示两端的设备名（鼠标停上去能看到实际用的关键字），中间是说明输入框，右边是删除按钮。说明随便填，停手半秒自动落盘。改完右上角会闪一下「已保存」。

**兜底规则**也可以拖：把右边任意一台麦克风拖到下面那条黄色横条上，它就变成兜底设备；旁边的「清除」把它取消掉。

配对写回的是 `rules.txt`，覆盖前会先把原文件另存为 `rules.txt.bak`，写盘走「临时文件 + 替换」，中途出错也不会只剩半个文件。改完程序自己重新加载，不用重启。

> 少数虚拟设备没有 `VID`，这种会用整段端点 ID 当关键字，同样能匹配上，界面上看到的还是设备名。

## 界面主题

右上角三段式切换，也可以从托盘菜单「界面主题」改：

| 档位 | 说明 |
| --- | --- |
| 跟随系统 | 跟着 Windows 的「应用模式」走，系统换成深色，界面跟着换 |
| 浅色 | 固定浅色 |

## 配置 rules.txt

`rules.txt` 放在程序目录里（安装版是 `%LOCALAPPDATA%\AutoMicSwitch`），界面上拖拽配对写的就是它。想手写也行，一行一条规则，格式是：

```
播放设备关键字|目标麦克风关键字|说明
```

`说明` 可以省略。关键字匹配的是设备硬件路径（InstanceId）的子串，一般写 `VID_xxxx` 就够。以 `#` 或 `//` 开头的行是注释。

兜底规则最多写一条，播放设备没匹配到任何规则时用它：

```
fallback=VID_9ABC     # 没匹配到时，麦克风切到这个设备
fallback=none         # 没匹配到时，什么都不做
```

一个完整的例子：

```
# 两副耳机各自用自己的麦克风
VID_1234|VID_1234|USB 耳机
VID_5678|VID_5678|第二副耳机

# 音箱 / HDMI / 板载输出一律用摄像头麦
fallback=VID_9ABC
```

界面上改完立刻生效。直接改文件的话，程序在启动时读一次，改完重启程序生效。文件不存在或者没写任何规则时，程序不会改动任何设备。

### 怎么查 VID

设备管理器 → 选中设备 → 右键「属性」→「详细信息」→ 在「属性」里选「硬件 Id」，会看到类似 `USB\VID_1234&PID_5678&MI_00` 的字符串，取 `VID_1234` 就行。

音频端点用的是它所在声卡的 VID，所以一副 USB 耳机的播放端和录音端通常是同一个 VID。

### 关键字写得更精确一点

关键字是子串匹配，`VID_1234` 会命中所有含这串的设备路径。如果同一台机器上有两个设备共用一个 VID（比如同一颗声卡下的多个接口），可以在关键字里带上后面的部分，例如 `VID_1234&PID_5678&MI_02`，匹配就更准。

注意有些主板和音箱会枚举出一个没有拾音孔的假麦克风端点，别把规则指到它上面。

## 开机自启

三种方式，效果一样：

1. 安装时勾选「开机自动启动」
2. 界面底栏勾选「开机自启」
3. 托盘菜单里勾「开机自启」

写的是 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下的 `AutoMicSwitch`，值形如 `"完整路径\AutoMicSwitch.exe" --startup`。任务管理器 →「启动应用」里能看到同名条目。

程序每次启动会对一遍这条记录：路径和当前 exe 对不上（比如换过安装位置）就自动改过来，不会出现自启指向旧目录的情况。

带 `--startup` 启动时不建窗口，只驻留托盘，省下 WebView2 那份内存；之后从托盘或快捷方式把窗口叫出来时再初始化界面。

## 自动更新

程序启动一分钟后查一次，之后每小时一次；托盘菜单点「检查更新」也可以手动查。

版本信息读的是 GitHub Release 里的 `latest.yml` 直链（`releases/latest/download/latest.yml`），不调 API，也就没有频率限制。查到新版本后：

1. 版本号变黄，底栏按钮变成「下载 vX.Y.Z」
2. 点一下开始下载安装包，下完用 `latest.yml` 里的 sha512 校验
3. 校验通过后按钮变成「重启并更新」，点了就退出、静默安装、自动重新启动

直连 GitHub 不通时会自动按常见本机代理端口（7890 / 7897 / 10809 / 1080 / 8118）逐个重试，都没通则提示去 GitHub 手动下载。走通的那条线路会记下来，后面直接用，不用每次都等直连超时一轮。

更新包里的运行库（WebView2 的两个托管 dll 和三套加载器）会跟主程序一起换掉，不会出现只换了 exe、dll 还是旧的这种情况。

## 从源码编译

`build.cmd` 用系统自带的 C# 编译器，不需要 Visual Studio，也不需要 NuGet。跑完产出 `dist\AutoMicSwitch-Setup.exe`。

分五步：

1. 用 `tools\IconGen.cs` 生成多尺寸 `app.ico`（画法取自 `src\AppIcon.cs`，和托盘图标、窗口图标共用一份）
2. 编译主程序到 `dist\tmp\AutoMicSwitch.exe`，界面页面作为资源嵌进去
3. 把主程序连同 WebView2 运行库铺一份到 `dist\payload\`，这份是可直接运行的同构副本，方便不安装就试
4. 把整套载荷当资源编进安装包
5. 收尾

WebView2 SDK 固定在 `lib\` 目录里随源码走（版本见 `lib\README.md`），构建时不联网。`lib\runtimes\` 下那三套加载器必须保持原目录结构，别拍平到 exe 旁边。

主程序 exe 只是安装包的素材，不单独对外发布。

在 Git Bash 里直接调 csc 的话，选项要改用 `-` 前缀（`-nologo`、`-target:winexe` 等），否则会被当成路径转换；跑 `build.cmd` 本身没这个问题。

改完代码重新跑一次即可。注意正在运行的程序会占着文件，重编前先退出。

## 发版

```
pack-release.cmd
```

先跑一遍 `build.cmd`，再生成 `dist\latest.yml`（版本、大小、sha512、更新说明取自根目录的 `release-notes.md`）。

发版时把这两个文件传进同一个 GitHub Release：

| 文件 | 作用 |
| --- | --- |
| `dist\AutoMicSwitch-Setup.exe` | 资产名必须叫这个，客户端按名字取 |
| `dist\latest.yml` | 客户端靠它比版本、核 sha512 |

版本号只在 `src\AssemblyInfo.cs` 里维护一处，程序里显示的、安装记录里的、`latest.yml` 里的都从它来。

## 工作原理

- 每 0.7 秒用 MMDevice API（`IMMDeviceEnumerator::GetDefaultAudioEndpoint`）读一次默认播放设备
- 发现变化后按规则找到目标麦克风，用 `AudioSes.dll` 里未公开的 `IPolicyConfig::SetDefaultEndpoint` 设为默认。`eConsole` / `eMultimedia` / `eCommunications` 三个角色一起设，效果等同于手动在设置面板里选
- 设置完在 2 / 4 / 6 秒各读回校验一次，被别的程序改回去会自动重试并记日志
- 界面是嵌在窗口里的 WebView2，页面（`Dashboard.html`）编译时嵌进 exe，通过 `NavigateToString` 喂进去。页面和 C# 之间走 `postMessage` 一问一答，没有本地端口、不监听任何网络、不联网、不上传任何数据
- 窗口收进托盘时页面停止轮询，避免空转
- 单实例运行：命名互斥量挡住第二个进程，同时第二个进程会置位一个命名事件，把已经跑着的那个的窗口叫到前面来（静默启动时窗口还没建，走事件一样叫得起来）

## 常见问题

**麦克风切完几秒又被改回去**

有别的音频软件在抢默认设备。日志里会连着写「被改回，重试」，找出那个软件关掉它的开机自启即可。常见的有各类耳机 / 鼠标的驱动中心、带音频管理的笔记本厂商工具。

**播放设备变了，麦克风没动**

看日志：

- 写「该播放设备无规则且未设兜底」→ 这个设备不在规则里，去配对板拖一条，或者设个兜底
- 写「找不到含 xxx 的麦克风」→ 目标麦克风当前不在线（耳机没插、摄像头没通电），或者关键字写错了

**界面打不开，或者只有一个提示窗口**

那台机器缺 WebView2 运行时。提示窗口里有下载按钮，装一次即可，装完点「重试」。Windows 11 自带；Windows 10 也可以让它随 Edge 一起更新装上。联动功能和界面是分开的，界面起不来不影响麦克风照常切换。

**界面白屏 / 界面进程崩了**

界面进程（msedgewebview2.exe）意外退出时窗口会切成原生提示页，点「重试」能重新拉起来。反复出现的话看日志里「界面进程异常」那一行的原因。

**换了 USB 口 / 改了设备名，要重新配吗**

不用。匹配用的是硬件路径里的 VID，跟插哪个口、显示叫什么名字无关。

**配对板上拖不动**

有些环境（远程桌面、触屏）里 HTML5 拖拽不好使，用「先点左边、再点右边」那条路，效果一样。

**规则不生效**

- 确认关键字是设备硬件 Id 里的子串，大小写不敏感
- 界面上改的立刻生效；直接改 `rules.txt` 的话要重启程序
- 改错了想回退：同目录的 `rules.txt.bak` 是上一次的版本

**想临时停一下**

界面点「暂停联动」，或托盘菜单选「暂停联动」。暂停期间只停止切换，程序还在跑。

**会联网吗**

不会。界面不走网络，程序只在检查更新时访问 GitHub。除更新外不发任何请求，也不上传任何数据。

**支持多用户 / 远程桌面吗**

程序按当前登录用户运行，自启写在 `HKCU` 下，只对当前用户生效。远程桌面切换会话时默认设备可能变化，程序会按规则重新匹配。

## 卸载

三种方式，效果一样：

1. Windows「设置 → 应用 → 已安装的应用」里找到 AutoMicSwitch，点卸载
2. 开始菜单里 AutoMicSwitch 目录下的卸载入口
3. 直接跑 `%LOCALAPPDATA%\AutoMicSwitch\Uninstall.exe`

卸载会先停掉正在运行的进程，再删掉程序文件、运行库、界面缓存、快捷方式、开机自启、主题偏好和卸载登记。安装目录里的 `rules.txt`（以及 `rules.txt.bak`）和日志会一并删除，要留的先备份。

不改动驱动和服务，删完就是彻底卸载。想静默卸载用 `Uninstall.exe /uninstall /S`。
